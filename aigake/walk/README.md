## 歩数と建築

最初の地区は「林間の町」（内部ID `grove`）に固定する。5棟、合計100,000歩で完成すると次の地域を選べる。2地区目以降は未着工の間だけ地域を選び直せる。完成時の余剰歩数で着工した場合は選び直せず、歩数を引き継いで建築する。既存の保存データの地域・進捗は変更しない。

日別の実測歩数と建築への加算済み歩数を分ける。日ごとに前回の最大取得値を保存し、同じ集計を取り直しても二重加算しない。下方訂正は記録に反映し、建築済みの町は巻き戻さない。導入前の歩数は記録表示のみで、建築へは加算しない。

初回は過去30日を取得。次回からは最後にデータが得られた日の7日前まで遡り、今日までを90日単位で読む。長い不在期間も処理し、空の応答では過去の記録を消さない。未取得日は0歩とせず「データなし」とする。

同期した歩数は、描画を始める前に保存する。`total` が確定済み、`seen` が見終わった地点。起動時は `seen` から `total` へ4〜9秒で再生し、ブロックと株単位の植物を既存の施工順で増やす。建物完成時には既存の地域ごとの住民と動物が現れる。スキップで確定状態に移り、再視聴は歩数を変更しない。演出途中で閉じた場合も確定歩数を保持し、表示した地点から続ける。OSの視差効果を減らす設定では演出を省く。

1棟20,000歩で順番に建築する。最初の1棟・ランドマークも現時点では同じ歩数。5棟の町は100,000歩、25棟の東京は500,000歩。景観と施工工程は既存の `town-plan.mjs` を使い、歩数の割り当ては `construction.mjs` に分離する。植生は町全体の進捗に沿って株単位で増える。

建築予定は町ごとに保存する。旧試作の保存データは実測歩数と完成履歴を維持し、完成した建物・建築中の進捗・表示済みの植生を引き継ぐ。施工中の棟は残り割合×20,000歩、未着工の棟は20,000歩となる。旧仕様で同時施工だった棟だけは移行後も並行する。完成後の余剰歩数は次の地域へ引き継ぎ、完成した地域のseed・建築予定・履歴を保存する。

## 記録

直近7日／30日の歩数、日別の棒グラフ、記録がある日の平均、建物の完成日と地域。距離・時間・消費カロリーは歩数から推定しない。完成日は歩数の加算日から求めるため、数日ぶりに起動した場合も全部を今日の出来事にはしない。歩数の訂正により完成履歴を繰り返し発行しない。

## タイムラプス

町の「タイムラプス」から完成済みの1棟、地区全体を再生できる。記録の完成履歴にも再生ボタンを置く。1棟は12秒で基礎→骨組み→壁・屋根→仕上げを近景で再構成する。地区全体は24〜60秒で順番に建築し、植生・完成に連動する住民や動物も再現する。地区全体はその地区の完成後に解放する。プレビュー環境だけは「地区全体を試す」で未完成の地区も一時的に再生でき、保存済みの進捗は変えない。

一時停止・再開・1/2/4倍速・シーク・もう一度に対応する。視差効果を減らす設定では停止状態で開く。バックグラウンドに移ると停止する。再生専用の状態と実測歩数台帳を分け、閉じると現在の町に戻す。同じWebGL描画領域を移して使うので、再生ごとにWebGLコンテキストを増やさない。

完成済み地区は保存したseedと施工予定から復元するため、次の地区へ移った後も再生できる。旧保存の施工予定がない地区は旧仕様で復元する。実際の画面録画ではなく現在のモデル・施工順による再構成で、動画ファイルへの書き出し・共有は未実装。

## 保存と配布

サイドロード用IPAの設定に「デバッグを開始」を追加。実データをコピーした独立した町で、＋100／1,000／5,000／20,000歩、任意の歩数、1棟完成、地区完成、初期化を試せる。「デバッグを終了」で実際の町に戻る。デバッグ中の端末歩数同期とWidget送信は停止し、星座帳も専用保存先を使う。`komorebi-walk-debug-v1` に保存し、実測・既存プレビューの台帳は書き換えない。TestFlightビルドでは入口を無効にする。localhostでは `/walk/?debug=1` で開く。

iOSでは小・中サイズのWidgetKitウィジェットへ、確定した町・建物の画像と歩数を共有する。`widget.mjs` とSwiftのWidgetBridgeを使い、Webのプレビューは共有対象にしない。アプリで同期した時点の情報を表示する。日付が変わった未同期の歩数はダッシュにする。実機ビルドの構成は `../app/README-ios.md`。

`komorebi-walk-health-v1` と `komorebi-walk-preview-v1` は独立したブラウザー内の台帳。ネイティブではWebViewの同じ領域を使う。壊れた保存データは初期化せずエラーにする。既存試作の保存キーには触れない。クラウド同期・端末間移行・アプリ削除後の復元は未実装。

実機の手順は [../app/README-ios.md](../app/README-ios.md)。ブラウザーの確認URLは `/walk/?demo=1`、実データ用は `/walk/`。設定の「散歩から戻る」はプレビューだけに表示する。旧実験ページからこのUIへ強制転送しない。
