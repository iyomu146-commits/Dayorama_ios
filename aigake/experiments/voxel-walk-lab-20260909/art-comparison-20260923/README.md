# Dayorama — 表現の比較 / 2026-09-23

共通の原案から、編集可能なボクセルと、形に合わせた部品のミニチュアを制作した独立した比較試作。本編への方式採用・移行は未決定。

現在は左に「窓と敷地」を表示する。「左の作品」で「前回の版」「初回」へ戻せる。右は初回の部品版。カメラ・一粒の寸法・光・露出は共通だが、作り込み版では形と配色を変更しているため、両画面を「同一形状の方式差だけ」とは扱わない。

「窓と敷地」は、不透明ガラスを壁から奥へ引き込み、周囲の壁・内枠・窓台と小鉢を立体化した版。中央の支柱はない。ガラスの反射模様は編集可能なセルの色で、写真投影や実際の店内ではない。敷地は浅い土の縁を持つ平らな輪郭へ変更し、大小の敷石で入口とテラスをつないだ。樹は枝が見える隙間を残し、葉の黄緑のコントラストを抑えている。

屋根は占有セルから連続した継ぎ目を作り、軒・棟を閉じた形にした。樹は幹・根・主枝・小枝をつなぎ、平たい葉の房を小さく不規則な樹冠へ変更。ベンチは5枚の座板、3枚の背板、肘掛け、座受けと横桟、椅子には座受けと貫を追加した。全て0.075mのセルとして保存される。窓は中央枠のない不透明ガラスを維持する。

`aigake` をWebルートとして配信し、`experiments/voxel-walk-lab-20260909/art-comparison-20260923/` を開く。外部API、外部CDN、課金サービスは利用しない。歩数・町の保存データを読み書きしない。

## 創作の循環を評価する

ユーザーが目指しているのは、一部の作者がボクセルで独自の形を作り込み、その高品質な作品を他の人が入手して歩行で建築する循環。用意した屋根・壁の組み合わせは、この自由な造形の代替にはならない。単体の完成図、建築途中、全景の読みやすさ、制作・改造の自由度、作者の作品を受け取る体験、端末負荷を分けて評価する。部品版の方がきれいという理由だけで移行を決めない。

## 操作

- 二画面のカメラが連動。単独表示、対象の切り替え、回転・拡大、背面、夜を確認できる。
- 共通の2万歩を基礎2,000、骨組み6,000、壁・窓12,000、屋根17,000、仕上げ20,000へ割り当てた。再生と手動スライダーがある。
- 左で一粒追加・削除・色変更、100操作まで戻す。完成状態で編集。回転は「眺める」へ戻す。
- 右は部品を離して確認でき、どちらも屋根色を変更できる。
- ボクセル作品はJSONへ書き出し、別の読み込みで同じ形を再現できる。途中の柱が完成後の壁で上書きされても、建築用の下層情報を保持する。
- 編集はこのページを開いている間のみ保持。残す場合は書き出す。読み込んだ作品は左だけに反映し、右が原案のままであることを表示する。
- 改修前・作り込み後・屋根色違い・読み込んだ作品の編集履歴は別々に保持し、切り替えで失わない。再読み込みで消えるため必要な作品は書き出す。対象の絞り込みは樹やベンチを単体で拡大する。

## 制作方式

原案は組み込み画像生成ツールで作成した。Meshyは使用していない。img2threejsの画像分析・構造仕様・厳格な仕様検査を使い、`design.mjs` に共通の寸法と部材を記述した。`render.mjs` はそれを直接立体化する手書きの描画処理であり、画像からの自動メッシュ抽出ではない。

ボクセルは1辺0.075mの一様格子。全てのセルを保持し、表示では隣接セルに隠れた面を省く。小物を非ボクセルの模型で置き換えて品質を補うことはしていない。細い線は連続したセルへ量子化し、薄い板は最低一粒を確保する。角の遮蔽をボクセルの頂点色へ反映。

部品は屋根の閉じた殻、壁の開口、枠、家具、枝、葉などの形状。表示時は同じ頂点属性を結合して描画負荷を抑え、選択用に部材と三角形の対応を保持する。描画の結合は編集用の設計情報を消さない。

色・光・露出・カメラは共通。窓は既存方針に合わせて不透明な色ガラス。中央の縦枠なし。原案に描かれた室内、樹皮・漆喰の細かな質感は未再現。原案との画像診断では形・画角の一致は合格基準未達で、img2threejs全工程の高忠実度合格とは扱わない。今回の成果は比較用の動作試作であり、両方式の最終品質の上限を示すものではない。

## 密度・範囲編集・5棟の比較

`density.html` は旧比較を残した独立試作。7.5cm / 15cmと、表面そのまま / 平面結合を切り替える。形の保存と描画を分離し、色・発光・頂点AOが一致する平面だけを結合する。細かい版の形や色を軽量化のために変更しない。陰影が不均一な面は結合しない。

| 敷地1組 | 保持セル | 建物・テラス | 表面の三角形 | 結合後の三角形 |
| --- | ---: | ---: | ---: | ---: |
| 7.5cm | 144,042 | 66,527 | 211,956 | 105,998 |
| 15cm | 25,074 | 11,773 | 50,236 | 26,874 |

数字はカフェ・樹・地面・小物の同じ1組。結合しても編集データのセル数は変わらない。15cm版は占有を残す縮約で、主屋幅64→32粒。家具・軒の細い部材が太り、ガラスの反射模様が粗くなる。粗い格子向けの再設計による品質改善は未実施。

建物単体で2点の範囲選択、塗装、充填、削除、オフセット複製、1/3/5粒幅の面追加、X=0を基準とする左右対称、30操作の取り消しができる。自由なセル造形を保持し、既製パーツの組み替えにはしていない。範囲は1操作40,000粒・作品240,000粒まで。7.5cm/15cmの編集は別々に保持。独立形式 `dayorama-density-study` のJSONで保存/読み込み。本編や旧比較との作品形式変換は含まない。

5棟の地区では同じ模型を5つ、樹5本、植物・家具、簡易住民12人を配置。完成した建物は形状を共有し、手前右の1棟だけ0〜20,000歩で建築する。住民は道路を周回し、夜は非表示。これは負荷検証用で、異なる建築物5種類や本編の生活行動の完成版ではない。

占有・工程・範囲編集・面作成をWorkerで実行。24粒単位の空間区画ごとに形状を保持し、編集や建築で変わった区画と隣接AOだけ作り直す。完成4棟は同じ結合済み形状を共有。カメラ回転だけでは静的な影を再生成せず、住民の影は最大10回/秒で更新。初期生成・密度変更時は全体を作り直す。

「25秒測る」は同じ画角・自動回転で完成10秒→建築15秒。結果は現在端末の画面更新間隔からのFPS、p95フレーム間隔、50ms超の数、Worker形状作成と往復応答時間。頂点量はアクティブ区画と共有模型の属性バッファのみで、全メモリ使用量ではない。GPU時間・発熱・電池消費は未計測。初期生成は測定外。背景タブ等の描画制限がある結果を端末性能として評価しない。iPhone実機評価はiPhoneでこの測定を実行する必要がある。

`node --test density.test.mjs` で面結合の面積・向き、区画境界、AO更新範囲、複製/対称/戻す、縮約前後の骨組み、実模型の屋根被覆、JSON往復と不正値を検査する。ブラウザー確認と制限は `evidence/density-review.md`。
