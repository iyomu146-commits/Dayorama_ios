# Dayorama ボクセル制作ノート

更新日：2026-09-23。林間の町の喫茶店を個別に再構築した経験を、次の建物・植生・小物の制作へ引き継ぐ。

**今回の方式は、全作品に適用する完成レシピではない。対象の特徴と問題に合う手法だけを選ぶ。** 形・配色・素材を喫茶店からコピーするのではなく、観察、比較、検査の手順と描画基盤を再利用して効率化する。

## いったん採用した基準

ユーザーの「いったんこれでいこうか」を受け、個別喫茶店の **roof13「屋根＋色と明暗」** を当面の制作基準として残す。15cm角の同一セル、面取りなし。屋根の段の配置、色のまとまり、素材別の表面表現と照明で仕上げた。

- [採用時の表示](./art-comparison-20260923/woodland/individual/cafe/evidence/roof13-match.png)／[変更前後](./art-comparison-20260923/woodland/individual/cafe/evidence/roof13-before-after.png)
- [元画像からの切り出し](./art-comparison-20260923/woodland/references/crops/cafe.png)／[参照との比較](./art-comparison-20260923/woodland/individual/cafe/evidence/roof13-reference-comparison.png)

これはユーザーによる暫定採用であり、全棟の完成や自動品質ゲートの合格を意味しない。歩行アプリへの統合・iPhone実機性能は未検証。個別制作したのは喫茶店だけで、住宅・パン屋・本屋・花屋は切り出し後の個別再構築が残っている。

## 次の対象で最初にすること

1. [画像生成ルール](./IMAGE-GENERATION-RULES.md)に従い、ゲームと同じ斜め平行投影・ボクセル表現で全景を設計する。
2. 採用した全景から対象を**実際に切り出す**。元画像・切り出し範囲・ハッシュを残す。別途生成した画像は補助資料と明記し、切り出しの代わりにしない。
3. 識別に効く特徴を絞る。例えば屋根の輪郭、庇と窓の比率、店先の用途、色の配置。背面など見えない部分は推定と分ける。
4. 対象固有の形を組み、同じ向き・大きさで比較する。修正は原則 **輪郭と比率 → 構造 → 色と明暗 → 素材の細部** の順に行う。
5. その対象を確認してから次へ進む。全景用の仮組みを、各棟の個別制作が済んだものとして扱わない。

窓中央の支柱をなくす、入口を塞がない、家具を接地させるなどの既存指定は継続する。参照画像に描かれていても構造上の誤りは写さない。植物や小物もそれぞれの輪郭・用途・接地・配置の余白を観察し、同じ手順で個別に確認する。

## 症状に合わせて選ぶ手法

| 症状・目的 | 今回有効だったこと | 適用を控える条件・注意 |
| --- | --- | --- |
| 屋根が横長の帯に見える | 瓦の列の開始位置を一部1セルずらし、段差と色をまとまりで配置する | 瓦の重なりが特徴の屋根向け。平屋根、金属・ガラス屋根、雪面には別の構成を設計する |
| 屋根の継ぎ目が穴に見える | 閉じた支持層を設け、くぼみの色を周囲の瓦へ近づける。ずらす列も細かく交互にしない | 構造検査が通っても、暗い色と影で穴に見えることがある。横からも見る |
| 建物が単色で平坦に見える | 屋根・壁・木部・窓の明るさを分け、同素材内にも近い色をまとまりで混ぜる | すべての建物を青緑屋根・クリーム壁にしない。地区内の統一感と棟ごとの識別を両立する |
| 壁や屋根が細かくまだらになる | セルごとの無作為な色変更を減らし、瓦・板・壁面の領域単位で色をまとめる | 模様そのものが特徴の対象は別判断。参照と通常表示で必要な大きさを選ぶ |
| 木・漆喰・煉瓦が同じ素材に見える | 素材別に粗さ・細かな凹凸・色むらを変える。木目は柱と横材で方向を変える | 拡大したときだけ見える細部に工数をかけすぎない。細部は小表示で弱め、ちらつきを避ける |
| 軒下や窓の奥が読めない | 主光・補助光・環境光と接点の陰影を調整し、奥行きの階層を作る | 影を強くするだけでは黒く潰れる。照明で形状の誤りを隠さない |
| 角がきれいすぎる | 今回は同一セルを保ち、形の段差・配色・表面表現で補う方を採用した | 面取りや変形を一律禁止する根拠ではない。使う場合は編集格子との整合、見え方、実機負荷を別に比較する |

喫茶店の屋根では、瓦幅4セル・10列に対し列のずれを `[0,0,1,1,0,0,0,1,1,0]` とした。これはこの屋根に合わせた実例であり、次の屋根の既定値ではない。支持層の厚さや瓦の寸法も対象ごとに決める。

## 色・明暗・質感で覚えておくこと

今回の喫茶店では、深い青緑の屋根と暖かい壁の差、木部・煉瓦・ガラスの明暗整理が、小さい表示でも形を読み取りやすくした。細かな表面模様だけを追加した段階では、屋根の大きな帯状の印象は解消しなかった。**シェーダーで直す問題と、形や色の配置で直す問題を先に分ける。**

色は素材ごとに数色から始め、部材・面の向き・まとまりに理由を持たせる。セルごとの強いランダム色差で情報量を増やさない。照明前の基本色と、光を当てた最終表示の両方を見る。夜の窓や街灯との整合は本体へ統合するときに別途確認する。

表面の細かな凹凸は今回、形を変えずに光への反応を変える方式を使った。参照画像の物理的な材質を復元したものではない。具体的な色コード・光の強さは[屋根の検討記録](./art-comparison-20260923/woodland/individual/cafe/ROOF-STUDY.md)に残すが、カメラ・露出・背景・描画方式が変われば調整し直す。

## 編集と描画を両立する

- 編集・保存の正本は整数座標の占有セルと色・材質情報。表示用の面の結合や質感処理によって、保存される形を曖昧にしない。
- 隠れた面を省き、条件の合う面を結合する。結合の条件には色・材質・陰影を含め、境界と占有セルが一致することを確認する。
- 素材の判定に、照明後の見た目の色を使わない。元のセル情報から材質を割り当てる。塗る・消す・追加する操作の後も属性を更新する。
- 表面模様を使う場合は、負の座標・六方向の面・分解表示でも継ぎ目や向きが破綻しないか確認する。
- 共有データには再現に必要なセル・パレット・仕上げの版を残す。見た目だけ作れても、読み込み後や建築途中に同じ状態を再現できなければ統合完了とはしない。

### 喫茶店で比較した描画量

| 比較版 | セル数 | 三角形数 |
| --- | ---: | ---: |
| 15cm・面取りなし、屋根変更前 material10 | 13,945 | 11,258 |
| 15cm・部材単位の仕上げ | 13,945 | 24,760 |
| 15cm・セルごとに面取り | 13,945 | 231,132 |
| 30cm・セルごとに小さな面取り | 2,939 | 54,672 |
| 当面採用：15cm・面取りなし roof13 | 13,856 | 13,018 |

同じ喫茶店の試作値であり、一般的な性能順位ではない。30cm化では細い部分の形も変わる。セル数が少なくても面取りで三角形は増える。roof13もセル数は減ったが、段差の露出面が増えて三角形は約15.6%増えた。22部材メッシュであり、影を含む総描画回数やiPhoneのFPSを示す値ではない。

セルの個数、三角形数、描画回数、シェーダー負荷、影、メモリを分けて考える。地区全体・建築途中・編集時の負荷を実機で確認するまで「軽い」と断定しない。

## 比較と検査を効率化する

1. 変更前を残し、同じカメラ・背景・出力サイズで比較する。形の確認時は光と基本パレットを揃え、色や照明も変えた完成案は比較条件を明記する。
2. 参照方向に加え、正面・左右・背面を見る。中立光と低い角度の光で、不自然な厚み・隙間・影を確認する。
3. 拡大図だけで決めない。今回は294×226ピクセルでも実際に描画して比較した。次の対象もアプリ内の表示サイズで読み取れるか確認する。
4. 接地連結、入口、家具の脚、屋根の閉鎖、煙突、ガラス、占有境界などを数値で検査する。その後、穴に見える影や部材比率などを目視で確認する。
5. 採用版・不採用版・理由・未確認事項を保存する。構造検査の通過、ユーザーの暫定採用、正式な品質ゲートの合格を混同しない。

本体へ入れる際は、2万歩の建築段階、部材の出現順、編集後と共有読み込み後、地区全景、昼夜、iPhoneでの動作を追加確認する。これらは今回の単体完成図の検査では済んでいない。

### 住宅での適用例

[住宅の個別試作](./art-comparison-20260923/woodland/individual/home/README.md)では、住宅の正本から形・開口・配色を独立設計し、表面生成と素材処理だけを再利用した。特に `cream` は住宅では漆喰であり、喫茶店の花・植栽向けの色名判定をそのまま使わない。材質分類と木目方向は対象側で定義する。

分解表示では、組み立て時に隠れていた面を対象部品のセルから再生成する。地面に落ちる影を建物の寸法検査へ混ぜない。小さな部品の色は全景の代表色だけで判定せず、遮蔽を保った部品ID画像の実際の可視画素でも確認する。元の不合格記録は残す。これらは各対象の問題に応じて使う検証上の知見であり、全棟の形を統一するルールではない。
